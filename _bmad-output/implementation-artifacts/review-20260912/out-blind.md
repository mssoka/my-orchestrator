This also contradicts the spec I/O matrix row "CheckRun pending, --allow-pending → exit 0 READY-qualified". Either required-gate membership must exempt explicitly-tolerated pending checks, or the flag must document that it only applies to non-required checks.

- **N05 fails open on partially-malformed incident entries (`.pi/extensions/nefario-watch.ts`).** The schema gate validates only that `incidents` is an array; entries failing the `id/name/status` field filter are silently **dropped**. If every listed incident is malformed (e.g. `{id, status}` without `name`) while `indicator` is `none`/`good`, `incidents.length === 0` → `clear` — a real unresolved incident is treated as recovery, violating the stated "invalid ≠ recovery / never clear without evidence" doctrine. In a DB missing only `pr_review` (the fallback's original scenario) but *having* `repo`, every bare-number PR loses identity resolution and is skipped with a health note — a needless degradation. - **The `EVIDENCE_MISSING` reason code spans both exit classes (`bin/pr_ready_core.py`).** The docstring/exit contract lists `EVIDENCE_MISSING` under exit 2 (UNKNOWN), but it is also emitted as a *blocker* (null `mergeable`, "required check(s) with no passing evidence") → exit 1, and the exit-1 reason list in the docstring hides it behind "…".
