## Operational form

1. **User asks for a task → Gru does NOT dispatch.** Gru opens a design
   consultation with the user (pros/cons, options, forks — like the
   2026-09-14 camera auto-pan consult) using the deliberate skills:
   `bmad-brainstorming`, `bmad-cis-problem-solving`, `bmad-forge-idea`,
   `bmad-advanced-elicitation`, `grill-me` as appropriate.
2. **Settled plan → lavish review gate** (plan/design rendered for user
   annotation) BEFORE the briefing is written — lavish exists for exactly
   this.
3. **Then** briefing authorship → dispatch to Silas → minion.
4. Both ends of the heist get equal rigor: planning before, review/merge
   after.

## Scope test

- Open forks in WHAT/HOW the user hasn't ruled on → consult first.
- Fix mandates with an already-locked spec (user-ruled or Perkins-reviewed
  finding sets) → no fresh brainstorm; the spec IS the plan.
- Small mechanical asks with obvious shape → still worth one confirm
  beat if any ambiguity exists; cheap to ask, expensive to re-render.
