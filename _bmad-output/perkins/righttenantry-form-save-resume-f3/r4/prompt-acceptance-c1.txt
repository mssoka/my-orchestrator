+## Intent
+
+**Problem:** The /apply form loses multi-session applicants: mandatory third-party reference letters take days to gather, but nothing persists before the final POST, so leaving is a dead end (root cause C2 of the 2026-07-31 completion session). Reminder stage-2 also still points at a blank form.
+
+**Approach:** Email-keyed server-side drafts saved (debounced) on stepper section change; a tokenized "Email me a link to continue" magic link (existing Resend path) restoring draft values into the SSR form; drafts expire at vacancy close via the retention job and carry a self-service erasure path; reminder stage-2 CTA becomes the per-recipient continue-link when a draft exists.
+
+Spec of record: `_bmad-output/planning-artifacts/problem-solving-application-form-completion-2026-07-31.md` (F3 row, risk table, success metrics). F1 stepper is MERGED (PR #561): `rt:form-step-changed` CustomEvent `{step_index, section_id, total}` fires on every user step change from `form_stepper.js` — that is the save hook.
+
+## Boundaries & Constraints
+
+**Always:**
+- No documents in drafts — field values only; files transmit only at the final POST (schema-verifiable: no content/storage-path columns).
+- No per-keystroke writes — debounce the step-change event; plus a `pagehide` beacon flush.
+- Never store the GDPR consent checkbox, honeypot (`_website`), or timing (`_form_loaded_at`) fields.
+- New endpoints are public (`is_public_path` + CSRF `should_skip` + `redact_token_route` arms) and must not weaken the `/apply/:code` contract or existing W0/F1 analytics events.
+- New applicant-facing copy lives in `application/form_copy.gleam`, brand voice (calm, specific; never "Error/Failed").
+- Migration is expand-only, applied ONLY to the local/test DB (never staging/prod); Squirrel codegen against the local test DB (field-notes trap: never `run_squirrel.sh` — it sources .env → staging).
+- Draft keyed `(vacancy_id, lower(email))`; the 288-bit `continue_token` (`wisp.random_string(48)`) IS the auth, same model as `application.erasure_token`.
+- On final submit, strip the matching draft (fields→`{}`, token→NULL, `submitted_at` set) — best-effort (fail-open, logged), never blocks submission.
+
+**Ask First:**
+- Deleting drafts immediately on manual vacancy close (default: daily retention sweep covers all closes) or adding Cloudflare edge rate-limit rules (Terraform) for the new endpoints.
+
+**Never:**
+- Never run migrations/Squirrel against staging/prod; never touch `.env`.
+- Never persist file data, file names-as-content, or storage paths in the draft.
+- Never leak whether a token/email exists (uniform friendly 404 on bad token; continue-link returns 200 regardless of send outcome).
+- No JS-FFI in Gleam; browser code is a plain static asset mirroring `apply_analytics.js`'s IIFE + CommonJS-export test pattern.
+- No changes to existing W0/F1 event shapes — additive only.
+
+## I/O & Edge-Case Matrix
+
+| Scenario | Input / State | Expected Output / Behavior | Error Handling |
+|----------|--------------|---------------------------|----------------|
+| Save | `rt:form-step-changed`, email filled | Debounced `PUT|POST /apply/:code/draft` upserts `(vacancy, email)`; first success fires PostHog `application_draft_saved` | Save failure silent (form still works); invalid/missing email → no save |
+| Tab close mid-section | pagehide with dirty state | `navigator.sendBeacon` flush | Best-effort; no retry |
+| Continue link | click "Email me a link to continue", valid email | Draft upserted, token ensured, Resend email with continue + erasure URLs; UI confirms "link sent" | <10 min since `last_link_sent_at` → 200, no email (cooldown); Resend down → friendly inline copy, draft kept |
+| Resume | GET `/apply/:code/resume/:token` | SSR form pre-filled from `fields`, restored banner, stepper starts at first incomplete section, `resumed_at` set once, PostHog `application_draft_resumed` | Unknown token → friendly 404; vacancy closed → existing closed page |
+| Resume + documents | draft restored | File inputs empty; documents step still gates — applicant re-attaches; banner copy says so | N/A |
+| Submit after resume | valid POST | Application inserted; draft stripped + `submitted_at` set | Strip fails → log only |
+| Expiry | vacancy closed or `closes_at` passed | Daily retention sweep deletes its drafts | Sweep failure logs + Sentry like other phases |
+| Erasure | GET+POST `/apply/:code/draft-erasure/:token` (link in continue email) | Confirm page → POST deletes → confirmation | Bad token → same friendly 404 |
+| Abuse | continue-link with victim email; oversize/odd payloads | Per-draft 10-min cooldown bounds sends; uniform 200; 64 KB body cap; server field-key filter | Reject oversize with 413 |
+| No-JS | form without JS | Long form, one POST, honest one-visit line stays (JS swaps copy only when saver active) | N/A |

+// Progressive enhancement ONLY: without this file the form is the honest
+// one-visit form the SSR prep-note describes. When active it:
+//   1. Saves the applicant's FIELD VALUES (never files, never the consent

+-- F3 save-and-resume: application_draft (2026-07-31 completion session,
+-- F3 row + data-protection risk row).
+--
+-- One row per (vacancy, applicant email) holding FIELD VALUES ONLY for an
+-- in-progress application, so a multi-session applicant can leave and
+-- resume via a tokenized magic link. Data-protection stance per the spec's
+-- risk table:
+--   * NO documents — files are only ever transmitted at the final POST;
+--     this table has no content/path columns by design.
+--   * Expiry — the daily retention job deletes rows whose vacancy is
+--     closed or past closes_at.
+--   * Erasure — the continue email carries a self-service delete link
+--     (POST /apply/:code/draft-erasure/:token) that removes the row.
+--   * Submit strip — a successful final POST empties `fields` and NULLs
+--     the token (the application row becomes the system of record);
+--     submitted_at keeps the resume→submit funnel metric DB-readable.
+--
+-- email is stored lowercased by the writer (landlord_email_lower_index
+-- precedent) so resume/upsert matching is case-insensitive without a
+-- functional unique index.
+--
+-- continue_token is 288 bits of URL-safe entropy (wisp.random_string(48)),
+-- same capability model as application.erasure_token: the token IS the
+-- auth. Partial unique index — most rows have NULL (token minted lazily on
+-- the first "email me a link" request).
+--
+-- vacancy_id ON DELETE CASCADE: landlord account deletion hard-deletes
+-- vacancies, and their drafts must go with them (no PII orphans).
+--
+-- Expand-only and idempotent; no existing rows touched.
+
+CREATE TABLE IF NOT EXISTS application_draft (
+  id                 UUID PRIMARY KEY DEFAULT gen_random_uuid(),
+  vacancy_id         UUID NOT NULL REFERENCES vacancy(id) ON DELETE CASCADE,
+  email              TEXT NOT NULL CHECK (length(email) BETWEEN 3 AND 320),
+  fields             JSONB NOT NULL DEFAULT '{}'::jsonb,
+  continue_token     TEXT,
+  last_link_sent_at  TIMESTAMPTZ,
+  resumed_at         TIMESTAMPTZ,
+  submitted_at       TIMESTAMPTZ,
+  -- Erasure tombstone: a confirmed Art. 17 deletion wipes fields/token but
+  -- keeps the (vacancy, email) key until vacancy close so a still-open form
+  -- tab's next auto-save hits the upsert's erased_at guard instead of
+  -- silently re-creating the PII payload. Email kept as a suppression
+  -- record (GDPR-recognised) and disclosed on the erasure confirm page.
+  erased_at          TIMESTAMPTZ,
+  created_at         TIMESTAMPTZ NOT NULL DEFAULT now(),
+  updated_at         TIMESTAMPTZ NOT NULL DEFAULT now()
+);
+
+CREATE UNIQUE INDEX IF NOT EXISTS application_draft_vacancy_email_key
+  ON application_draft (vacancy_id, email);
+

+  ON application_draft (continue_token)
+  WHERE continue_token IS NOT NULL;
