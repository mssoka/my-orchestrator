## The seam (rule 4)

The codebase **has** a central PDF renderer — `audit_report.generate` → the shared Typst template. One seam, both producers:

- `generate(data:, priv_dir:, watermark: Bool)` — when `True`, appends `--input watermark=true` to the typst argv; when `False` the argv is **identical** to the pre-change pipeline.
- `audit_report.typ` — a `demo-watermark` layer (`DEMO`, DM Sans 700, 64pt, muted-red at 25% alpha, rotated 40°, centered) attached to the page background of **every** page, plus an explicit `place` at the end of the cover block (the cover paints a full-bleed navy block over the background). When the flag is absent the layer resolves to `none` — verified byte-identical.
- Callers: runtime handler → `watermark: False`; demo pre-bake → `watermark: True`.

## Decisions & rationale

- **Flag on `generate`, not a second demo detector** (rule 1): the canonical demo check is client-side (`model.demo_mode` — landed by #636); the server has no demo mode. The pre-bake tool *is* the demo producer, so the flag is passed at its single call site — no second detector invented.
- **Metadata normalization, not `--creation-timestamp`**: pinning typst's clock would change real-mode PDF metadata for everyone; instead the test strips the two known non-deterministic fields (timestamps, instance ID) and compares everything else byte-for-byte. The normalizer covers all six byte patterns empirically observed across compiles.
- **25% alpha, muted-red, 40°**: chosen from three alpha variants (15/25/35%) via vision review — visible at a glance on both the navy cover and white interiors, unobtrusive to read through.
- **Golden re-bless policy**: a legitimate template change that alters real-mode output requires a deliberate re-bless of `server/test/fixtures/real_mode_report_golden.pdf` (same discipline as the demo PDFs).
- **bmad-build waiver (canon note)**: the briefing's skills policy names `bmad-quick-dev`, which forwards to `bmad-build`; that render path is broken on this install (`ambiguous config token implementation_artifacts` — `_bmad/config.toml` + `_bmad/bmm/config.yaml` both define it; no `_bmad/scripts/render_skill.py`). Waived per the standing Silas ruling (2026-08-21) — the briefing was already a complete self-contained spec and was executed as such.
- **Demo document uploads excluded**: their storage hrefs point at files that do not exist server-side; no bytes are produced for them in either mode (out of scope of "PDFs produced in demo mode").
