### Blockers (1)

1. **Security-definer view `inbound_email_sender_state` bypasses RLS — exposes enquirer emails to the public anon key** [security] — `supabase/migrations/20260731213000_add_inbound_email_sender_state_view.sql:22`
   Postgres views run as their owner by default, so this view bypasses the RLS the project auto-enables on every public table (`20260512175704_canonical_rls_auto_enable.sql` covers CREATE TABLE only — it cannot fire for views). Supabase's default privileges grant SELECT on new public-schema relations (views included) to `anon`/`authenticated`, and PostgREST auto-exposes them — so the shipped anon key can read per-vacancy enquirer email addresses (PII) and reminder state unauthenticated. The migration comment "No RLS surface change" is wrong for views.
   **Fix:** recreate the view `WITH (security_invoker = on)` so base-table RLS applies to non-service roles, and/or add `REVOKE SELECT ON inbound_email_sender_state FROM anon, authenticated;`. The service_role server path is unaffected either way.
